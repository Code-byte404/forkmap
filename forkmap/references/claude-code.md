# Forkmap in Claude Code

In Claude Code you have a shell and the session transcripts on disk, so Forkmap can do two things the app version can't:

- **Read the original text from the transcript**, not from your context. Context may have been compacted, but the transcript keeps every turn verbatim, so quotes stay exact.
- **Persist the map per project, across sessions.** Each run adds to `.forkmap/forkmap.json` in the project, so options parked in last week's session are still on the map today, and the user can reopen the session they came from with `claude --resume`.

Steps 2–4 of SKILL.md (finding forks, deciding statuses, the data fields, the output-language rule) apply unchanged. This file replaces step 1 (where the text comes from) and step 5 (how the map is shown), and adds storage.

`<skill-dir>` below is this skill's base directory, shown when the skill loads.

## Files

All state lives in `.forkmap/` at the project root (the current working directory; use the git root if the user is in a subdirectory):

| File | Role |
| --- | --- |
| `forkmap.json` | Source of truth. You read and edit it. |
| `forkmap.html` | Clickable tree, generated by `render.py`. Never edit by hand. |
| `FORKMAP.md` | Text tree plus a list of sessions with resume commands, generated by `render.py`. Never edit by hand. |

The first time `.forkmap/` is created, tell the user in one line that it holds the map and that they may want to add it to `.gitignore` if they don't want it committed. Don't edit `.gitignore` yourself. This line is the one exception to the two-sentence reply limit.

## Step 1: Get the turns

Which session to scan:

- Default: **the current session**.
- If the user names other sessions ("also last session", "all sessions this week"), list them with `python3 <skill-dir>/scripts/transcript.py sessions` and pick from that list. Scan each session separately.

Extract the turns:

```bash
python3 <skill-dir>/scripts/transcript.py turns --session current --out /tmp/forkmap-turns.txt
```

Then read that file. Use `--session <id-prefix>` for another session. Use `--from N` to read only from turn N on (see incremental runs below). If the file is long, read it in parts rather than skipping any; per-reply text is capped at 6000 chars by default (`--max-reply 0` lifts the cap if a list got truncated).

Check before you trust it:

- "current" means the most recently written transcript in this project. Confirm turn 1 matches how this conversation actually started. If it doesn't (another session in the same project was written to more recently), run `transcript.py sessions`, find the right one, and pass its id.
- The last turn in the output is normally the Forkmap request itself. Exclude it, as SKILL.md says.
- The transcript format is internal to Claude Code and can change between versions. If the script errors or the output looks wrong (no turns, garbled text), say so, and fall back to the conversation in your context for the current session, noting that quotes may be less exact if the context was compacted.

## Step 4 additions: the stored data

`forkmap.json` uses the data format from SKILL.md step 4, with these changes for multiple sessions:

```json
{
  "title": "Forkmap · ForkMap",
  "topic": "ForkMap",
  "lang": "en",
  "project": "/Users/me/code/ForkMap",
  "sessions": {
    "9b35784e-60ed-4e78-bccb-8dc26a8e8052": {"title": "Claude App skill draft", "date": "2026-10-19", "scanned": [1, 13]}
  },
  "forks": [
    {"id": "1", "session": "9b35784e-60ed-4e78-bccb-8dc26a8e8052", "turn": 3, "said": "Can it be drawn as a tree",
     "title": "Map format", "parent": null, "quote": "...", "options": ["..."]}
  ]
}
```

- `topic` is the **project directory name** here, not turn 1 of a session, because the map spans sessions. `title` is `Forkmap · {topic}`. Once set, never change either.
- `project`: absolute path of the project root. The page uses it to build `cd "<project>" && claude --resume <session>`, the real way back to a fork in Claude Code (a resumed session must be started from its project directory).
- `sessions`: one entry per scanned session. `title` comes from the `# title:` line of the transcript output (or a short summary of turn 1 if empty), `date` is the day of turn 1, `scanned` is the turn range covered so far.
- Every fork gets `session`, and `said` (the verbatim opening of the user's message in that turn, max 20 characters, skipping placeholders like `[Image #2]`) instead of the top-level `turns` map, since turn numbers repeat across sessions. Options appearing in a different turn than their fork may carry their own `said`.
- Drop the top-level `scanned` and `turns` keys; per-session `scanned` replaces them.
- Fork `id`s run 1, 2, 3… across the whole project and are never reused or renumbered.
- `lang` and `ui` follow the output-language rule in SKILL.md. They are stored in the JSON, so every later run reuses the same translated labels. If an existing map is in one language and the current conversation is in another, keep the map's language and `ui` so the file stays consistent, and reply in the conversation's language.

## Incremental runs

Read `forkmap.json` first if it exists.

- For a session already in `sessions`, extract only the new part (`--from` the turn after `scanned[1]`, minus one turn of overlap so a list right at the boundary isn't missed). Add new forks and extend `scanned`.
- New turns can change the status of **any** existing fork, including ones from older sessions. If the user picks up a parked option today, mark it `active` and update its `summary` ("picked up on 2026-10-21").
- A fork that was `pending` gets normal statuses once a later turn picks from it or moves on, per SKILL.md step 2.
- When the user changes a status by hand ("mark #3-B rejected"), set it and add `"pinned": true` to that option. Never change a pinned option's status from your own inference; only the user can change it again.
- Keep everything else as it was: ids, titles, quotes, summaries the user didn't ask to change.

Write the updated JSON with your file tools, then render.

## Step 5: Render

```bash
python3 <skill-dir>/scripts/render.py .forkmap/forkmap.json --open
```

This writes `forkmap.html` and `FORKMAP.md` next to the JSON and opens the HTML in the browser. Pass `--open` only when the user asked to see the map; skip it when you are updating the map as part of another task. Don't paste the tree into the chat. The reply stays at two sentences in the conversation's language, as in SKILL.md, and adds the path of `FORKMAP.md`. For example: "Scanned turns 1–13 of this session: 4 forks, 3 options not taken; map opened in the browser and saved to .forkmap/FORKMAP.md."

On the page, every node shows which session it came from, and a button copies the `claude --resume` command for that session.

## Follow-ups in Claude Code

Same as SKILL.md, plus:

- **Expand an option from another session**: you can't jump into that session from here. Either continue the direction in this session using the stored quote and summary as context, or give the user the resume command and let them choose.
- **Remove a fork** the user says is wrong: delete it from the JSON (its id stays retired) and re-render.
